## 本次更新（9.10.3 → 9.10.5）

> **代码回调 + 发布说明生成器 + 甘特图**：新增两张表（由幂等升级自动建立），覆盖解压并执行升级后生效。

### 新增：代码平台 Webhook 接入（push 事件）

后台「代码回调」新增公开接收端，代码平台 push 后即时把提交注释里的对象编号写入操作记录，
不再依赖 cron 拉取。原有的 git/svn 拉取式**保留**，供内网无外网回调的场景使用。

- 支持 **GitHub / GitLab / Gitea**；入口为 `/repohook.php?token=<令牌>`，令牌由系统生成。
- **签名校验**：GitHub/Gitea 走 `X-Hub-Signature-256`（兼容 `sha1`），GitLab 走 `X-Gitlab-Token`；
  密钥为空时一律拒绝，签名错误也会写入接收日志。
- **只处理 push**：按裁剪范围，MR/issue 事件只记日志不处理；提交注释用 `task #12` / `bug #34` /
  `story #56` 关联对象，与既有 git/svn 拉取式同一套解析规则，**只记录关联动作、不改变对象状态**。
- 每次接收（含失败）写入接收日志，便于排障。

### 新增：发布说明生成器

发布详情页新增「生成发布说明」：按 **需求 / 已修复 Bug / 遗留问题** 分组渲染 markdown，
一键复制，可直接粘贴到 GitHub Release 或 `doc/release-notes/`。不存在或已删除的对象会被自动过滤。

### 新增：项目甘特图

项目任务页新增「甘特图」入口：用 eCharts 只读渲染任务的起止日期、完成进度与状态配色。
无完整起止日期的任务不参与展示；不支持拖拽改期。

### 是否建议升级

- **建议**。三项均为增量，不影响既有功能。
- **需要执行升级**：本版新增 `zt_repohook` / `zt_repohooklog` 两张表，由升级流程的幂等方法自动建立；
  不执行升级会导致「代码回调」页面报错。全新安装的 `db/zentao.sql` 已同步。
- 使用代码回调前，请先在「后台 → 代码回调」创建一条配置，把生成的 URL 与 Secret 填入代码平台。

### 验证记录（本地 dev 站）

- **代码回调**：正确签名 + 3 个提交（2 个含对象编号）→ `handled 2 commit(s)`，task/bug 各写入一条
  `gitcommited` action（actor / comment / commit 前 10 位均正确），无编号的提交不写入；
  错误签名 → `invalid signature`；空密钥 → `invalid signature`；非 push 事件 → `ignored`；
  未知令牌 → `unknown hook`；缺令牌 → `missing token`；以上均落接收日志（未知令牌因无 hookID 不落）。
- **发布说明生成器**：空关联时输出三个「（无）」分组；关联真实对象后分组与数量正确，
  已删 / 不存在对象被过滤；复制按钮点击后提示「已复制」。
- **甘特图**：有任务的项目渲染 5 条；无带日期任务的项目显示空状态提示；任务页入口存在。
- 全量 PHP 语法检查 1211 文件 0 失败。
